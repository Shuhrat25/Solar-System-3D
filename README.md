# Космический исследователь

[Открыть демо](https://solar-system-3-d-gamma.vercel.app/)

Интерактивная 3D-Солнечная система на **React + Three.js**. Сайт открывается
кинематографичным пролётом к Солнцу, после чего управление переходит к
пользователю: он летает между планетами на ракете (или в скафандре космонавта)
и читает о каждом мире.


## Запуск

```bash
npm install
```

```bash
npm run dev
```

Сборка для публикации:

```bash
npm run build
```

Готовые файлы появятся в `dist/` — это статика, её можно выложить на любой
хостинг.

## Управление

| Клавиши | Действие |
| --- | --- |
| `W` / `↑` | тяга вперёд |
| `S` / `↓` | тормозной импульс |
| `A` `D` / `←` `→` | поворот |
| `R` `F` | тангаж вверх и вниз |
| `Q` `E` | крен |
| Зажатая мышь | штурвал: чем дальше от точки нажатия, тем резче манёвр |
| `Shift` | форсаж |
| `Пробел` | гашение скорости |
| `Esc` | вернуться к свободному полёту |

Клик по планете или строке в панели «Маршрут» включает автопилот: корабль
уходит по дуге к цели, выходит на орбиту и открывает карточку планеты.
На орбите мышь вращает камеру вокруг планеты, колесо приближает.

## На телефоне

Сенсорная раскладка включается сама — по `pointer: coarse` или узкому экрану.

| Жест | Действие |
| --- | --- |
| Стик слева внизу | поворот и тангаж |
| Кнопка «ТЯГА» | двигатель вперёд |
| Кнопка «ФОРСАЖ» | разгон на полную |
| Тап по планете | автопилот к ней |
| Лента сверху | выбор цели из списка |
| Свайп по небу | штурвал |

Что меняется, кроме управления:

- список планет превращается в горизонтальную ленту «фишек», телеметрия — в
  узкую строку, подписи кнопок сжимаются до иконок;
- карточка планеты выезжает снизу как шторка, а камера в этот момент
  поднимает планету в верхнюю треть кадра, чтобы её не закрывало;
- учитываются вырезы экрана (`env(safe-area-inset-*)`) и горизонтальная
  ориентация;
- профиль качества `src/quality.js` режет нагрузку: текстуры вдвое меньше по
  стороне (вчетверо меньше пикселей и времени генерации), звёзд 3600 вместо
  9000, астероидов 800 + 480 вместо 2200 + 1400, ниже `dpr` и число сегментов
  сфер. На слабых устройствах (≤ 4 ядер или ≤ 4 ГБ памяти) режется ещё сильнее
  и отключается свечение.

## Как устроено

```
src/
  data/planets.js      Солнце, 9 тел, спутники, тексты и характеристики
  store.js             zustand: режимы и выбор; объект flight — данные кадра
  quality.js           профиль качества сцены: телефон / десктоп / слабое железо
  hooks/useInput.js    клавиатура, «мышиный стик», сенсорный джойстик
  hooks/useIsMobile.js реактивный признак сенсорной вёрстки
  three/
    textures.js        процедурная генерация всех текстур на <canvas>
    Scene.jsx          сборка сцены, свет, bloom
    Sun.jsx            шейдер плазмы, корона, источник света
    Planet.jsx         поверхность, атмосфера, кольца, спутники, подпись
    Orbits.jsx         линии орбит и пояса астероидов на инстансах
    Starfield.jsx      звёзды, туманности, близкая пыль
    Spaceship.jsx      ракета, космонавт, частицы выхлопа
    CameraRig.jsx      вся логика полёта и камеры
  ui/                  HUD, карточка планеты, загрузка, заставка
```

Несколько решений, которые стоит знать при доработке.

**Текстур нет в репозитории.** Поверхности планет, облака, кольца и блики
рисуются на `<canvas>` из трёхмерного value-шума при загрузке
(`generateAllTextures`). Шум берётся в точках на сфере, поэтому текстура
бесшовна по долготе. Плюс: проект автономен и весит мало. Минус: старт
занимает пару секунд — это время и показывает экран загрузки.

**Состояние разделено на два слоя.** В zustand лежит только то, что меняется
редко (режим, выбранная планета, настройки). Позиция, скорость и дистанции
живут в обычном объекте `flight` и обновляются в `useFrame`, а HUD читает их
через `requestAnimationFrame` и пишет прямо в DOM. Иначе React
перерисовывался бы 60 раз в секунду.

**«Вперёд» — это −Z**, как у камеры Three.js. Поэтому для разворота корабля
используется `lookRotation()` на базе `Matrix4.lookAt`, а не
`Object3D.lookAt`: последний направляет на цель +Z и переворачивает
ориентацию на 180°.

**Масштаб условный.** 50 единиц сцены = 1 а.е. Радиусы планет сильно увеличены
относительно расстояний, иначе они были бы неразличимыми точками. Скорости
орбит подчиняются третьему закону Кеплера: `ω = k / r^1.5`.

**Порядок кадра задан приоритетами `useFrame`.** Камера и корабль считаются
раньше остального (`-2` и `-1`), чтобы сцена рисовалась уже по новой позиции.
Отрицательные приоритеты не отключают автоматический рендер, положительные —
отключают.
